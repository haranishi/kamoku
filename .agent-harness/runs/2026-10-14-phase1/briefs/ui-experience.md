# 体験の評価（評価者への依頼書）

あなたは評価者です。kamoku を**自分で操作して**、使い勝手を採点します。コードは見ません（画面を起動する以外に、リポジトリのファイルを開かない。設計書も読まない）。

kamoku は、日本の個人事業主が、自分のパソコンの中だけで帳簿をつける会計ソフトです。ブラウザで開く業務用の画面で、数字と名前は合成データです。

## 受け入れてほしい設計判断（覆す提案は不要）

- 自動仕訳（AIの提案）、銀行・カードの自動取得、請求書、申告書・e-Tax は作っていません（権利と法務の確認が済むまで）。無いことは減点しません。将来の置き場所の案は書いてかまいません。
- 主役は、キーボードだけで速く記帳できること（ショートカット、Tabの順、Ctrl/Cmd+Enterでまとめて確定）。マウスでも迷わず使えることも、同じ重さで見ます。
- 手元だけで動きます。ログイン、クラウド、外への通信はありません。
- 台帳は追記だけです。訂正・取消は、理由を残す新しい記録になります。
- 色は藍が主で、朱は訂正・取消・失敗だけです。

## この評価の主題: 「慣れの近さ」

日本の主要なクラウド会計サービス（個人事業主向け）を使い慣れた人が、説明なしで迷わず使えるかを見ます。見るのは、操作の順番、用語（仕訳・勘定科目・取引先・口座・確定）の置き場所、押す所の意味、一覧から登録・確定までの流れです。一般にこう置かれる型から外れていて戸惑う所と、その型に寄せる案を書いてください。

- **実際の製品の画面を見に行かない・使わない**（外部のサイトを開かない）。あなたの一般的な知識で判断します。
- **特定の製品の画面・文言・アイコン・配色を写す提案は書かない。製品名も書かない。** 提案は、「一覧の上に絞り込みを置く」のような型のレベルにします（権利の方針です）。

## 起動と操作

- 起動の補助: `exp-server.sh`（依頼文に場所と環境変数）。`start <名前> demo` で架空の事業（記帳・取込・帳票）、`start <名前> empty` で空の帳簿（初期設定）が起動し、合言葉つきのアドレスが出ます。**最初に、そのアドレスを開きます。** 終わったら `stop`。
- 操作の道具: `agent-browser`。最初に `agent-browser skills get core --full` を読み、**すべてのコマンドに `--session <あなたの名前>` を付けます**（ほかの評価者と別のブラウザになります）。画面の状態は `snapshot`（文字の木）で確かめ、画像は節目だけ撮って開きます（1回の評価で開く画像は30枚まで。同じ画像を開き直さない）。キー操作は `press` と `keyboard type` で、人と同じように。
- 幅は、指示がなければ 1440×900。狭い幅の確認は `set viewport 390 844`。
- 日本語入力（変換中のEnter）は、この環境では試せません。「未確認」と書きます。
- リポジトリのファイルを書き換えない。ほかの評価者のセッションに触らない。

## 出力の形式（Markdownだけ）

1. **操作の記録**: 手順ごとに「やったこと → 起きたこと → 引っかかり」。節目の画像のファイル名を添える（画像は指定のフォルダに保存）。
2. **採点表**: 10項目の点数と、根拠を1行ずつ（何をしたら何が起きたか）。合計と、合格か。
3. **不具合・詰み**: 点数とは別に、再現手順つきで全部（小さなものも）。
4. **慣れの近さ**: タスクごとに、戸惑う点と、型に寄せる案（上の決まりを守る）。
5. **改善指示TOP5**: 「どこを・どうする」まで具体的に。
6. **確かめられなかったこと**。

点が甘くなることを避けてください。実装者の説明を信じず、自分で操作した結果だけで書いてください。
