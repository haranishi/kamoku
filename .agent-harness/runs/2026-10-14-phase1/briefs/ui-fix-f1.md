## P1: 試験を緑にし、3人の採点役が口をそろえた指摘を直す

1. **AC-11.7（押せる大きさ）の共通部分。** 幅1024未満で44×44px以上。左上の製品名のリンク（28×28）、上の欄のアイコンのボタン、下のバー、サイドバーの開閉、タブ、分節ボタン、選択欄、期間の「‹」「›」、チェックとラジオ（包むラベルを含めて44）。共通のCSS（`base.css` `components*.css`）で直す。文章の外のリンクに付ける `.tap`（`components.css` に用意済み）を使ってもよい。F2が各画面のリンクに `.tap` を付けるので、`.tap` の定義は変えない（足すのはよい）。
2. **AC-11.6（隠れる列と省略）の、帳票と共通部分。** 試算表（幅390）と月次推移（幅390・768・1440）は、横に隠れる列を無くす。総勘定元帳（幅768）も。方針は「幅に合わせて列を畳む」:
   - 幅640未満: 試算表と月次推移は、カードの積み上げ（科目名／月を見出しにして、期首・借方・貸方・期末、または売上・経費・利益を、ラベルつきの行で右寄せ、重要な数字を太く）。`components/table.js` のカード表示を使ってよい（必要なら部品を拡張する）。
   - 幅640〜1023: 総勘定元帳は、No・相手科目を摘要の2行目の小さな文字に畳み、日付・摘要・借方・貸方・残高の5列を、枠に収める。
   - 月次推移の表（1193px）は、なぜそんな幅になるのかを調べ、列を畳むか、行と列を入れ替えて、全幅に収める。
3. **固定バーの下の端（AC-11.8）。** 下のバーは `bottom: 0` で、固定や貼り付きのバーは、下の端からの距離を変数 `--bar-bottom`（`tokens.css` に用意済み。幅767以下は下のバーの高さ、それ以外は0）で決める。下のバーと固定バーの間に隙間を作る設計をやめる。未確認の `.inbox-bar` 自体はF2の担当（F2が `--bar-bottom` を使う）。あなたは、ほかの固定・貼り付きの要素（ダイアログの下のバー、トースト、`entry` の保存バーを除く共通の部品）が、下のバーの隙間から本文をのぞかせないことを確かめ、「固定バーは、下の端にぴったり付き、背景は不透明、上に区切りの線」という決まりを `layout*.css` にコメントで書く。
4. **色の意味（共通部分）。** 共通の `ui-fix-common.md` の「色の決まり」どおりに:
   - サイドバーの未確認の件数（`layout.css` の `.nav-badge` 付近）を、藍の淡い色にする。
   - 損益計算書・月次推移・貸借対照表の「赤字」の札（`report-table.js` の `.rt-loss`）を `badge--muted` に。
   - 消費税の「参考値」の帯（`report-views2.js` の taxView）を `banner--info` に。
   - ダークの凡例「選んだ月（網かけ）」の見本（チャート）が、背景に溶けて見えない。枠線か、差が3:1以上ある色にする。
   - ダークで、未選択のチェックボックスが「使えない」ように見える。枠を `--c-border-strong` にして、塗らない。
   - 小さな補足文・「必須」・ショートカットの小枠・サイドバーのラベルの色と大きさ。ダークでも読める濃さにする（サイドバーのラベルは幅768で10px前後。12px以上に）。`check-contrast.mjs` に、足した組を加えて通す。
5. **選択欄の統一。** 標準の `<select>`（税区分・年・月・文字コード・端数処理）と、自作の候補つき入力（科目・口座・取引先）で、矢印の太さ、文字の大きさ、高さ、枠を同じにする。標準の `<select>` は `appearance: none` にして、自作と同じ矢印を `mask` か `background` で付ける（CSPで `img-src 'self' data:` が許されている。`check-policy` の決まりを確かめる）。
6. **語の途中の折り返し（帳票）。** 科目名・口座名の列は `.keep`（`word-break: keep-all; overflow-wrap: anywhere`）にし、表の見出しや数字の列は `white-space: nowrap`。説明文は、入力欄の幅に合わせず、カードの幅まで広げ、`text-wrap: pretty` を足して、「してくだ／さい。」のような行末の取り残しを避ける。
7. **シェア（上の欄、下のバー、サイドバー）。**
   - 上の欄の「取引を登録」は、枠だけのボタン（二番手）にする。塗りの主ボタンは、各画面の主な操作に1つだけ。
   - デモの帯は、1行、小さく（幅390で高さ40px以下）、藍の枠をやめて無彩色寄りに。
   - 下のバーの「メニュー」は、下のバーに無い画面（帳票・口座・勘定科目・取引先・設定）にいる間、選ばれた表示にする。
   - アイコンだけのボタン（検索、表示の切替、サイドバーの開閉）に、`aria-label` と `title` を付け、幅1024以上では、名前が分かる形にする。
8. **チャートの「記録のない月」。** 収益も経費も0の月は、点も線も描かず、線を切る（0へ急に落ちて見えるため）。月次推移の表では、その月を「—」（`emptyValue()`）にする。凡例の下の「表で見る」は、すぐ下に月ごとの数字の表があるなら、重複しないようにする（表を既定で開いておき、開閉をやめる、など）。

## P2: 視覚階層と、広い幅の左寄り

9. **帳票の見出しの帯。** タブ → 期間 → 内容 → 書き出し、の順にする。期間は「‹ 2026年 ▾ ›」のような1行にまとめる。CSV書き出しは、表の下か、控えめな「書き出し」ボタンにして、最初の1画面を数字に使う。損益計算書・試算表・消費税で、「書き出し」の見出しと欄が、「期間」の欄より12pxほど下にずれている（幅1440）のを直す。帳票の6つの切替は、幅640未満では、2段に折り返さず、横にスクロールする1段にする（選ばれたものが見える位置に寄せる。続きがあると分かる影を付ける。このスクロールは、`data-allow-hscroll` を付けてよい、唯一の例外）。
10. **幅1440の左寄り。** いまは、損益計算書・消費税・月次推移の中身が左の約760pxで止まり、右の約350pxが空く。損益計算書は、幅1100以上で「収益」と「費用」を左右2列にする（貸借対照表と同じ組み方）。消費税は、税区分の表を左、結論（売上税額・仕入税額・納付額の見込み）を右に。月次推移の表は、グラフと同じ全幅に。表の行の見出しと金額の間が離れすぎる（約700px）ところは、表の最大幅を決めて、行をたどりやすくする。
11. **結論の数字を大きく。** 損益計算書の「当期純利益」と、消費税の「納付額の見込み」は、ホームの数字のカードと同じ大きさ（約24px）で、表の上に出す（色だけで区別しない）。貸借対照表は、左の「資産の合計」と右の「負債と資本の合計」を同じ高さにそろえる（両側の列を同じ高さにして、合計の行を下端に寄せる）。「一致しています」の緑の札は、文字を12px以上に。
12. **0の扱い。** 試算表の0は、薄い色（`--c-muted`）にして、実際の金額が先に目に入るようにする（0を「—」に置き換えない。0は意味のある数字）。
13. **日付と円の書き方。** 総勘定元帳の日付は、仕訳帳と同じ「2026-09-10 (木)」にそろえる（`formatDate`）。円は `money()` にそろえる。空は `emptyValue()`。
14. **ダイアログ。** 確定ダイアログなどの「ラベル：値」の行で、ラベルの下端が値より上にずれる。ベースラインでそろえる。背景の幕を少し濃くして、後ろの固定バーの塗りのボタンが目立たないようにする。ダイアログが開いたとき、最初のフォーカスの輪が見えること。
