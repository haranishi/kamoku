## 区切り2（仕事2 欄の誤りを読み上げに届ける: 済み）

- `fields.js` の `field()`: 誤りの入れ物（`p.field-error`）に、空のうちから `aria-live="polite"`。
  `setError` は、同じ文なら何もしない。文は1つの文字の節（Text）の中身だけを書き換える（初めての誤りのときだけ、印と
  `span.field-error-text` を足す）。保存の検査（`entry-simple-check.js` の `pick`）が「消してすぐ同じ文を入れ直す」とき、
  描く前に元どおりになり、読み上げの木の節も同じもの（Chromium の CDP で、作り直すと id が 689→701 に変わり、書き換えでは同じ）。
  `clearOnInput` は、出ている文があるときだけ消す（前は `errorEl.firstChild` を見ていた）。外から見える使い方は同じ。
- `components.css`: `aria-live` の付いた誤りの入れ物は、空のとき `display: none` にせず、見えない1pxの形（`position: absolute`、
  `clip`）で置く。表示しない入れ物に文を入れても、読み上げソフトが新しい文として読まないことがあるため。並びから外れるので、
  欄の間隔は前と同じ（前も空のときは `display: none` で場所を取らなかった）。`role="alert"` の入れ物（小窓・取込など）は変えていない。
- 読まれ方（確かめた範囲は DOM と読み上げの木まで。実際の読み上げソフトでは聞いていない）:
  - 欄を出た時点の誤り（金額「12a3」→Tab）: 入れ物に文が入る→polite で1回読まれる。同じ文のまま、もう一度欄を出ても、要素は変わらない。
  - 保存の検査で一度に複数の欄に誤りが出るとき: **新しく出た誤りだけ**が、欄ごとに1回ずつ polite で順に読まれる。
    前から出ていて文の変わらない誤りは、読み直さない。R の「N か所を直してください」（role=alert）と重なるのは、新しく出た誤りの文だけ。
- 試験: `ui/tests/fields.test.mjs` に3件（空のうちから polite／同じ文・消して入れ直しで作り直さない／clearOnInput）。
  `e2e/shell.spec.mjs` に1件（登録の金額「12a3」→Tab で、空のうちから在る領域に文が出る。空の入れ物は見えず場所を取らない。
  同じ文で欄を出ても要素が変わらない。部品をその場に置き、消して入れ直しても読み上げの木の節が同じ）。
  壊して赤くなることを確かめた: 単体3通り、通し3通り（作り直す／空の入れ物を display: none に戻す／文が変わるたびに作り直す）。
