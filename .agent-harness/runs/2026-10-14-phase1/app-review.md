# サーバー（kamoku-app）の読み取りレビューと、対応

別の担当（Codex・読み取り専用）が `kamoku-app` を読み、12件の指摘（A1〜A3、B1〜B9）と、直さないと決めた1件を出しました。実装担当が直し、設計担当が、品質の門と変異試験を自分で流し直して確かめました（2026-10-14）。

コードや試験のコメントにある「A1」「B6」などは、下の表の指摘の番号です。

## 対応の一覧

| 指摘 | 問題 | 対応 | 守っている試験 |
|---|---|---|---|
| A1 | 再送防止の表が、本文をそのまま持ち、0.5MBの本文50件で約26MBに膨らむ | 本文のSHA-256と最初の応えだけを持つ。`client_id` は64バイトまで。表は10分・1万件・8MBまで | `src/api/entries_tests.rs`、`tests/entries.rs` |
| A2 | 表が上限を超えると、期限内の記録を追い出し、最初の要求の再送で仕訳が二重にできる | 追い出さず、新しい印の要求を保存の前に `503 busy` で断る。同じ印と本文の再送は、いっぱいでも200 | `src/api/entries_tests.rs` |
| A3 | `/drafts/confirm` に15万件の番号を送ると、20秒待っても応えが無い | 送った要素が2,000件を超えたら、何も始める前に `422`。重なりの除去を集合で行う | `tests/bounds.rs` |
| B1 | 別の接続が科目や設定を変えても、メモリの値のまま保存される | 保存層に `refresh_masters`。変更の要求（プレビューを含む）の前に読み直す | `kamoku-store/tests/refresh.rs`、`tests/server.rs` |
| B2 | 処理が途中で止まると、ロックが汚れたまま、次の要求が通らない | 保存層に `recover`（開いたままの取引を戻し、読み直す）。ロックが汚れたら呼ぶ | `src/app/tests.rs`、`kamoku-store/tests/refresh.rs` |
| B3 | `demo` が、目印のある既存のフォルダを消す | 起動のたびに新しい `kamoku-demo-<乱数>` を0700で作る。既存のフォルダは消さない | `tests/cli.rs` |
| B4 | `--ui-dir` の中のリンクで、開発用のファイルや README を配れる | 正規化したあとの相対パスにも、同じ禁止の規則を掛ける | `src/statics.rs` の試験 |
| B5 | 未確認の出金の合計が、安全な整数（2^53−1）を超えても200で返る | 超えたら `422 amount_range` | `tests/bounds.rs` |
| B6 | 取込の確定で、列の対応の保存に失敗しても、下書きが残る | 列の対応を先に保存してから、下書きを入れる | `tests/failures.rs` |
| B7 | `/imports/batches` の `offset` と `total` が無い | 読めた新しい順の500件から、`offset` と `limit` で切り出す | `tests/bounds.rs` |
| B8 | 処理のスレッドを待つ間の時間が、期限に入っていない | 受け付けた時から期限を数え、過ぎた接続は読まずに408で閉じる | `tests/http_queue.rs` |
| B9 | HEAD への断りの応えにも、本文が付く | 断るときは、HEAD に本文を付けない（期限切れと混雑は、要求を読む前なので付ける） | `tests/http_queue.rs`、`tests/http_robust.rs` |
| — | `100 Continue` に共通の見出しを付けない | 直さない。中身の無い合図で、ブラウザは表示に使わない。理由をコードのコメントに書いた | — |

## 確かめた結果

- 品質の門6つ（書式、clippy、全試験、文書の警告、最小のRust 1.88、cargo deny）: 終了コード0。試験は263件が通り、失敗は0件。
- 変異試験: サーバーの35件、保存層の2関数の5件、保存層の14件が、すべて検出（生き残り0）。実装担当の報告のあと、設計担当が同じ一覧を別に流し直して、同じ結果を得た。
- 実際のバイナリでのスモーク試験29項目、本物のサーバーでのブラウザの通し試験143件、契約試験25件: すべて通過。

## 仕様に反映したこと

通信の約束（`docs/spec/api-*.md`）に、再送防止の上限と `503`、確定の2,000件、`/imports/batches` の `total`、受け口の限界、変更の要求の前の読み直しを足した。
