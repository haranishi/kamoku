# Rustの部品の読み取りレビューと、その対応（2026-10-14）

実装の直後に、別のモデル（Codex。読み取り専用）に、`kamoku-ledger` `kamoku-books` `kamoku-import` `kamoku-store` を点検してもらいました。指摘は15件（🔴4、🟡10、⚪1）でした。再現できるものは、先に再現する試験を書いて赤にしてから直しました（Codexの別のコピーで修正し、私が差分を読んで本体に取り込みました）。

| # | 指摘の要点 | 判断 |
|---|---|---|
| S1 🔴 | 強制取込が、同じファイルの新規行を重複扱いにして落とす（強制行が先に出現番号を使うため） | 直した。挿入の前に全行を分類し、新規を先に入れ、強制の行にそのあとの番号を振る |
| S2 🔴 | `INSERT OR REPLACE` が、削除トリガーを発火させずに、追記専用の表の行を置き換える | 直した。4表に `BEFORE INSERT` のトリガーを足し、衝突を断る |
| I1 🔴 | 同じ列を10万回指定する対応で、小さな入力から数GBの文字列を作れる | 直した。摘要の列は8個まで、連結の途中で1000バイトを超えたら、その行を読めない行にする |
| S3 🔴 | 付随情報や明細が壊れていると、接頭復元でなく起動全体が失敗する | 直した。イベントごとの復元の結果として持ち、孤立した行は破損として読み取り専用にする |
| S4 🟡 | 巻き戻しのあとの再読込に失敗すると、保存されていない仕訳がメモリに残る | 直した。再読込に失敗したら台帳を空にして読み取り専用にする |
| I2 🟡 | CSVの列数と総セル数に上限がない | 直した。1行1,000列、全体200万セル |
| I3 🟡 | 1001バイトの摘要は取り込めるが、確定できず、直せない | I1で直した。読み取りの時点で読めない行にする |
| S5 🟡 | 確定のときの付随情報の照合が片方向で、余計な取引先を混ぜられる | 直した。許す鍵（`invoice_no` `draft` `source`）以外の余計な鍵を断る |
| S6 🟡 | 保存APIが、未知の税区分、`NT` の税額、読み戻せない日付（負の年）を保存する | 直した。保存の直前に税区分と日付の範囲を検査する |
| I4 🟡 | 壊れた引用符（`"1"00`）を金額として黙って受理する | 直した（仕様の解釈。厳しい側）。閉じた引用符のあとの文字は、行番号つきで断る |
| B1 🟡 | 事業主勘定の子の科目だけ、翌年に残る | 直した。祖先に事業主貸・事業主借を持つ科目も、年の初めに0から始める |
| B2 🟡 | 仕入と全額の返品で、経過措置の控除額が相殺されない（−1円） | 直した（仕様の解釈）。絶対値を0へ向かって切り捨て、符号を付ける。仕様書も直した |
| S7 🟡 | 既存の任意のフォルダの権限を0700に変える | 直した。新しく作るフォルダだけ0700 |
| ⚪ | 保存層に、400文字を超える行があり、読みにくい | 直した。100文字以内、SQLは名前つきの定数に |

確認した範囲で問題なしだったもの: 標準科目での仮想の繰越、試算表・貸借対照表・元帳の整合、事業主貸・借の損益除外、家事按分の端数、通常のDB失敗時の巻き戻し、Staleの検出、SQLのパラメータ化、本番コードの `unwrap` と `panic`、桁あふれ。

直したあとの検証: 5つのcrateの試験は151件がすべて通りました。修正を外すと赤くなることを、12指摘で確かめています（Codex。復元は `cmp` で確認）。
