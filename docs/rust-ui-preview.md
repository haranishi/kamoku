# 移行初期の仕訳帳を別の経路で検証する

全画面は[通常のRust UI](rust-ui.md)へ移行しています。`/rust/index.html` は最初に移した仕訳帳の互換経路として残し、検索、絞り込み、50件ごとの一覧、履歴と通常画面への往復を専用試験でも確認します。

この経路も、通常の画面と同じWASM生成物を使います。起動パスによってRustの入口を選びます。JavaScriptの旧画面へ戻す経路ではありません。

## ビルドと専用試験

[初回の準備](rust-ui.md)とブラウザの準備を済ませてから、次を実行します。

```sh
bash tools/build-rust-ui.sh
python3 tools/test-rust-ui.py
```

最後の試験は、本体をビルドして合成データのサーバーを起動し、埋め込みWASMをChromiumで操作します。検索、合計、ページ、履歴、詳細からの復帰、IMEの模擬、応答の競合、通信失敗からの再試行、安全な文字表示を確かめます。

起動時のアドレスから認証してから、同じオリジンの `/rust/index.html` を開けます。必要な生成物が無ければ本体のビルドは失敗します。

`e2e/rust-ui-results/` に390／768／1440pxの画像と計測JSONを出します。CIがアップロードするのは合成データの画像と計測値だけで、認証URL・サーバーログ・トレース・録画を含めません。

## 計測の意味

専用試験の表示時間は、通常のRust画面と互換経路の比較です。どちらも現在のWASMを使うため、以前のJavaScript版との移行前後比較には使えません。言語の移行による速度は、同じブラウザ・合成データ・サーバーの条件で別に測ります。

実機のIME、読み上げ、Safari、Firefox、Windowsの確認範囲は[試験の地図](testing.md)を参照してください。
