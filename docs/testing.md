# 試験の地図: 何を、どの層で、どうやって確かめているか

kamoku の試験は11の層に分かれています。下の層ほど速く、失敗の場所を絞りやすい。上の層ほど本物に近く、部品の組み合わせまで確かめます。PRの前は、`tools/check-all.sh` と `cd e2e && ./run-real.sh` を流してください。件数は 2026-10-14 時点です。

## 層ごとの役割

| 層 | 確かめること | 流し方 | 件数 |
|---|---|---|---:|
| 部品（Rust） | 金額、税、集計、台帳の符号化、CSVの読み取り。性質の試験（proptest）つき | `cargo test -p kamoku-ledger -p kamoku-jp-tax -p kamoku-books -p kamoku-import` | 122 |
| 保存層（Rust） | SQLite、追記専用、起動時の検証、下書きの確定、別の接続との競合 | `cargo test -p kamoku-store` | 41 |
| サーバー（Rust） | 実際のソケットでAPIを通す。入口の守り、失敗の形、上限、外へ通信しないこと | `cargo test -p kamoku-app` | 100 |
| 別実装の照合 | 台帳のハッシュを、Pythonで計算し直して比べる | `python3 tools/verify-ledger-golden.py` | 7値 |
| 画面の単体試験 | 金額の式、日付、IMEの判定、絞り込み、帳票の親子、取込の列 | `node --test ui/tests/` | 78 |
| 画面の静的検査 | 色の組のコントラスト（AC-11.2）と、禁止事項の文字列 | `node ui/dev/check-contrast.mjs`、`node ui/dev/check-policy.mjs` | 64組、104ファイル |
| スモーク | 実際のバイナリを起動して、入口・貸借の一致・書き出し・巨大な要求への耐性を外から見る | `python3 tools/smoke-demo.py` | 29項目 |
| ブラウザの通し試験 | 本物のサーバーを相手に、キーボードだけの流れまで通す | `cd e2e && ./run-real.sh flows` | 143 |
| 契約試験 | 模擬サーバーと本物の、応えの形が同じか | `cd e2e && ./run-real.sh contract` | 25 |
| スクリーンショット | 全画面を3つの幅とライト・ダークで開き、描画できることを確かめて撮る | `cd e2e && ./run-real.sh screens` | 150枚 |
| 変異試験 | わざと誤りを入れて、試験が赤くなるか | `python3 tools/mutate.py tools/mutations/<名前>.json` | 92 |

## 試験が「門番」になっているか

試験が通っていても、守りたい規則を守っているとは限りません。そこで2つの道具で、試験の側を確かめます。

**変異試験**は、ソースの1か所を壊して試験を流し、赤くなれば「検出」、ならなければ「生き残り」と数えます。生き残りは試験の穴です。92件の変異は、按分の丸め、締めの境界、重複取込の番号、追記専用の仕掛け、再送防止の上限など、壊れると帳簿が狂う所を選んであります。2026-10-14 の時点で、生き残りは0件です。CIでは流さず（重いため）、手元で流します。

**契約試験**は、画面の開発と一部の試験に使う模擬サーバー（`ui/dev/mock-server.mjs`）が、本物と違う形を返していないかを見ます。値ではなく、キーの有無と型だけを比べます。画面を模擬サーバーに合わせて作ると、本物では動かない、という穴ができるためです。最初に流したとき、期間エラーの `field` が違っていたので、模擬サーバーの側を直しました。

## 仕様との対応

画面とサーバーの約束は `docs/spec/` の受け入れ条件（`AC-02.1` など）に書いてあります。72件の条件のすべてに、試験からの参照があります（人が確かめる6件を除く）。`python3 tools/check-spec-trace.py` が、参照の無い条件を一覧します。試験の名前かコメントに条件の番号を書けば、参照として数えます。

## CIで流れるもの

PRごとに、次のジョブが流れます（`.github/workflows/ci.yml`）。

- 試験（Linux と macOS）: 書式、clippy、全試験、文書の警告
- 最小のRustバージョン（1.88）、依存のライセンスと脆弱性（cargo deny）、ライセンス表示（REUSE）
- 文書のリンクと行数、台帳の固定値の別計算、受け入れ条件の対応
- 画面の単体試験と静的検査
- 本物のサーバーでの通し試験: バイナリのビルド、スモーク、ブラウザの通し試験、契約試験、スクリーンショット
- 秘密情報の走査（gitleaks）

## 自動では確かめていないこと

次は、人が確かめる必要があります。確かめた結果は、Issueに残してください。

- **本物のIME、読み上げ、Safari、Firefox。** 通し試験は Chromium だけです。変換中のEnterで確定しない仕組みは、ChromiumのIME模擬で確かめていますが、実機のIMEでの確認は残っています。
- **Windows。** CIは Linux と macOS だけです。Windows向けの置き場所（`%APPDATA%`）とブラウザを開く処理は書いてありますが、動かして確かめていません。
- **キーボードだけで100件を確定する時間**（AC-05.6）。自動実行では1行あたり4.31回のキー押下で、6.8秒でしたが、人が測った記録はまだありません。目標は5分以内です。
- **ExcelでのBOMつきCSVの表示**（AC-13.2）、**初めての人が15分以内に起動できるか**（AC-12.3）、金額の桁がそろって見えるか（AC-11.5）。
- **税の計算の正しさそのもの。** 試験は、仕様どおりに計算することを確かめます。仕様の側（税率、端数処理、経過措置の表）は、税理士の確認を受けていません（[規制の調査](legal/regulation-notes.md)）。

## 試験を足すとき

- 条件を満たす試験なら、名前かコメントに `AC-xx.y` を書く。
- 守りを足したら、その守りを外す誤りを `tools/mutations/*.json` に足して、赤くなることを確かめる。
- 画面と本物のサーバーの間の約束を変えたら、模擬サーバーも直し、契約試験を通す。
- 合成データだけを使う。実在の帳簿・口座・店の名前は入れない。
