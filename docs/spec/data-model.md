# データの形

保存先は、1つのSQLiteファイルです。ここには、設計の判断と、守るべき決まりだけを書きます。列の定義は `crates/kamoku-store` の移行ファイル（`migrations/`）が正本です。

## 3つの層

| 層 | 入るもの | 変え方 |
|---|---|---|
| 台帳 | 仕訳のイベント（登録・訂正・取消）、明細、付随情報 | 追記だけ。SQLiteのトリガーが更新と削除を拒む。ハッシュで連鎖する |
| 下書き | CSVから取り込んだ明細（未確認）、取込の記録 | 自由に変えられる。連鎖の外にある |
| マスタ | 勘定科目、取引先、設定、取込の列対応、テンプレート | 変えられる。変更は変更履歴に追記する |

台帳に入れるのは、あとから変わると帳簿の意味が変わるものです。日付、摘要、明細（科目コード・貸借・金額・税区分・税額・メモ）、そして付随情報（取引先の名前、登録番号、入力の種類、事業の割合、取り込み元）です。付随情報は、`kamoku-ledger` の `Entry::meta` に入れ、ハッシュの対象にします。科目の表示名やマスタの行は対象外で、台帳は科目の**コード**だけを持ちます。表示名を変えても、連鎖は壊れません。

## 表の一覧

| 表 | 役割 |
|---|---|
| `meta` | スキーマの版、作成日時、アプリの識別 |
| `settings` | 設定（事業者名、課税の区分、登録番号、端数処理、開業日、締めた日、初期設定の完了） |
| `accounts` | 勘定科目と口座。口座は、型（現金・預金・カード・電子マネー）を持つ科目 |
| `partners` | 取引先（名前、読み、登録番号、メモ） |
| `ledger_events` / `ledger_lines` / `ledger_meta` | 台帳。1イベント、その明細、その付随情報 |
| `import_batches` / `drafts` / `import_profiles` | 取込の記録、未確認の明細、口座ごとの列の対応 |
| `templates` | よく使う取引の入力 |
| `change_log` | マスタと設定の変更履歴（追記のみ） |

## 守るべき決まり

1. **台帳は追記だけ。** 3つの台帳の表に、更新と削除のトリガーを置く。連番は欠けない。
2. **起動のたびに、連鎖を最初から検証する。** 失敗したら読み取り専用で起動し、最初に壊れた連番と規則を画面に出す。自動で直さない。
3. **書き込みの順序。** 入力を `Entry::new` で検証し、メモリ上の `Ledger` に追記し、同じイベントを1つのトランザクションでSQLiteへ書く。取引先の自動追加、下書きの状態の更新、変更履歴も、**同じトランザクション**に入れる。書き込みが失敗したら、DBから台帳を読み直して、メモリを戻す。
4. **下書きの重複防止。** 下書きには、(指紋, 出現番号) の一意制約を置く。指紋は、口座・日付・符号つき金額・正規化した摘要のSHA-256（取引番号の列があれば、口座と取引番号）。同じ指紋の行は、ファイルの中の順に1, 2, ... と番号を振る。この方式は、期間が部分的に重なるファイルで、同じ内容の本物の取引を落とすことがある。重複と判定した行は、理由つきで利用者に見せ、選べば取り込める。そのときの出現番号は、その指紋の最大の番号+1にする。
5. **下書きの状態。** `draft`（未確認）、`confirmed`（確定済み。`entry_id` を持つ）、`ignored`（取り込まない）。確定した行は消さない。指紋を残して、再取込で復活しないようにするため。
6. **科目のコードは変えない。** 一度使ったコードは、再利用も改名もしない。分類（資産・負債・資本・収益・費用）は変えない。無効にはできる。口座は削除できない。
7. **金額は整数の円。** 1明細は9,999,999,999,999円以下（ブラウザの数値で正確に扱える範囲）。
8. **時刻は信用しない。** `recorded_at` はこの機械の時計の秒で、信頼できる時刻の証明ではない。
9. **権限。** 保存先のフォルダは0700、DBファイルは0600（Unix系）。
10. **SQLiteの設定。** WAL、`foreign_keys=ON`、`synchronous=FULL`、`busy_timeout=5000`。
11. **移行。** `PRAGMA user_version` で版を持つ。移行は前にしか進まず、番号つきのSQLファイルで書く。古い版のDBから移行する試験を、版ごとに置く。
12. **バックアップ。** `VACUUM INTO` で、一貫した複製を作る。

13. **別のプロセスが書いたとき。** 書き込みの前に、DBの末尾の連番とハッシュが、メモリの台帳と同じかを、同じトランザクションの中で確かめる。違えば、台帳を読み直して `stale` を返す。二重起動を禁じはしない（ほかの道具でDBを読むのは許す）。
14. **壊れていたとき。** 連番・連鎖の検証に失敗したら、壊れた連番の手前までで台帳を作る。DBの行から `Entry` を作り直せない行も、その連番で壊れているとみなす。件数は、DB全体と読み込めた分を分けて返す。壊れた先を使って新しく書くことはしない。
15. **ファイルの権限。** DB本体、`-wal`、`-shm`、バックアップ、書き出した一時ファイルは、同じ権限（0600）にする。フォルダは、新しく作るときだけ0700にし、すでにあるフォルダの権限は変えない（共有フォルダやカレントディレクトリを巻き込まないため）。バックアップは、別名で最後まで書いてから本来の名前に移す（途中で止まった不完全な複製を残さない）。Windowsは、利用者のプロフィール内の既定の保存先（`%APPDATA%`）の権限に任せ、独自の設定はしない。
16. **集計の桁。** 1明細の上限に加え、ブラウザの数値で正確に扱える範囲（9,007,199,254,740,991）を超える集計値は返さず、`amount_range` で断る。

## 仕訳の付随情報（`meta`）の鍵

鍵は半角の小文字・数字・`_` `-` `.`、1〜32バイト。値は1000バイト以下。1仕訳に16組まで。

| 鍵 | 値 |
|---|---|
| `kind` | `expense` `income` `transfer` `journal` `opening` |
| `source` | `manual` `import` `template` `opening` `demo` |
| `partner` | 取引先の名前（入力時点の文字列） |
| `invoice_no` | その時点の取引先の登録番号 |
| `business_pct` | 事業の割合（0〜100） |
| `draft` | 取り込み元の下書きのID |

## 仕訳No

画面に出す「No.97」は、登録イベントの出現順の番号です。保存はせず、読み込み時に数えます。訂正しても変わりません。

## 端数処理の決まり

- 家事按分: 事業分 = 支払額 × 割合を円未満で四捨五入。残りは事業主貸。
- 消費税額: 税込の事業分から、設定の端数処理（切捨て・四捨五入・切上げ）で税額を出す。1つの請求書の税率ごとの集計とは違う、記帳上の目安である。
