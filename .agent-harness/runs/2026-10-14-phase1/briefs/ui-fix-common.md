## 実測で確かめた事実（採点役の指摘のうち、本物の画面で裏が取れたもの）

- 幅390の試算表と月次推移の表が、横にスクロールする枠（`.table-wrap`）の中で、531px・1193pxの幅に対して356pxしか見えていない。貸方・期末の列が隠れる。
- 幅768の総勘定元帳の表が、733pxで626pxの枠に入らない。勘定科目の表は、読み・コード・税区分が「…」で省略される。
- 未確認の下の固定バー（`.inbox-bar`、`position: sticky`）は、幅390で `bottom: 68px`（下のバーの高さ60pxに8pxの隙間）、幅1440で `bottom: 12px` にある。この隙間から、後ろのカードの縁と文字がのぞく。
- 押せる場所のうち、文章の外にあるリンクが16〜22pxの高さしかない（経費の上位5科目、口座の一覧、No.195、この口座の元帳）。左上の製品名のリンクは28×28px、「くわしい条件」は32px。
- 選択欄は、自作（科目・口座・取引先）と標準（税区分・年・月）で、矢印の太さと文字の大きさが違う。
- 同じ橙系（`--c-pending-bg` と `--c-warn`）が、「訂正」「赤字」「参考値の注意」「サイドバーの未確認件数」の4つに使われている。

## 色の決まり（今回、はっきりさせる）

- **朱（`--c-danger`）は、訂正・取消・失敗のためだけ**に使う。費用の金額には使わない。
- 「赤字」の札は、朱でも橙でもなく、無彩色の札（`badge--muted` と注意のアイコン）にする。赤字は、文字と符号で示す。
- サイドバーの未確認の件数は、藍の淡い色（`--c-primary-soft` と `--c-primary`）にする。橙ではない。
- 「参考値」などの注意の帯は、藍の情報の帯（`banner--info`）にする。橙（`--c-warn`）は、保存前の入力の警告や、確定の前の注意（未保存、候補にできない行）だけに残す。
- 「訂正」の札は朱の淡い色（`badge--danger`）、「取消」も朱。文字で区別する。
- 色は `css/tokens.css` の変数だけを使う（部品のCSSに16進を書かない）。コントラストは `node ui/dev/check-contrast.mjs` で確かめる。

## 書き方の決まり（これまでと同じ）

- 画面の要素は `dom.js` の `h()` で作る。`innerHTML`、`style` 属性、インラインの `<style>`、外のURL、`api.js` 以外からの `fetch` は使わない（`node ui/dev/check-policy.mjs` が見張る）。
- 画面の日本語は、やさしく、短く。「シームレス」「強力な」などの決まり文句、英語の略語、専門用語を増やさない。
- 1つのJSファイルは300行を目安に分ける。コメントは「なぜ」だけ書く。
- キー操作は、`js/ime.js` の `shouldIgnoreKey` を最初に呼ぶ決まりを守る。キーボードだけで速く記帳できる作りを、壊さない（幅1440の流れは、既存の e2e が守っています）。
- 他の会計ソフト（freee・マネーフォワード・弥生・GnuCashなど）の画面・文言・配色・アイコンを真似ない。依存を足さない。

## 確かめる手順

コピーの中で、次を使います（`KAMOKU_BIN=/tmp/kamoku-docs-target/debug/kamoku` を先に export する。これは本体で作った実行ファイルで、読むだけ）。

```
node --test ui/tests/
node ui/dev/check-contrast.mjs
node ui/dev/check-policy.mjs
cd e2e && ./run-real.sh flows layout.spec.mjs -g "AC-11.6"     # 段階の名前のあとの引数は Playwright に渡る
cd e2e && ./run-real.sh flows                                   # 全部（約2〜3分）
cd e2e && ./run-real.sh contract
```

- 並行して動かす相手と、Playwrightの作業ファイルがぶつからないよう、`export KAMOKU_E2E_OUT=<コピー>/.pw-out` と `export KAMOKU_SCREENS_OUT=<コピー>/.shots` を付けてください。
- 見た目は、スクリーンショットで確かめます。`./run-real.sh screens`（150枚。1〜2分）を `KAMOKU_SCREENS_OUT` に出し、**自分で Read で開いて**見ます。1回に開く画像は25枚までにし、同じ画像を何度も開かない（上限に当たります）。縦に長い画像は縮小されて読めないので、必要なら一時の Playwright の小さなスクリプトで、画面の高さ（390×844、768×1024、1440×900）の撮影や、一部の切り抜きを作ってください。一時のファイルは、終わるときに消します。
- 直す前に、直す場所を実測して確かめてください（採点の指摘には、撮影の都合で生じた見え方の違いも混ざります）。実測で再現しない指摘は、直さず、理由を報告に書きます。
