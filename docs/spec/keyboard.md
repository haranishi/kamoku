# キー操作と日本語入力

このアプリの中心は、キーボードだけで記帳を終えられることです。決めごとを先に書きます。

## 日本語入力（IME）の決めごと

変換を決めるためのEnterが、仕訳の確定や候補の選択として働いてはいけません。キーを押したときの処理は、この順に判定します。

1. `event.isComposing` が真なら、何もしない。`preventDefault` もしない（変換の動きを邪魔しないため）。
2. `event.keyCode` が229のとき、または `compositionend` から50ミリ秒以内のEnterは、アプリの処理をしない。ただし `preventDefault` する。Safariは、変換を決めるEnterの `keydown` を、`compositionend` の**後**に、`isComposing` を偽にして送るので、そのままだとフォームの暗黙の送信や保存が動いてしまう。
3. `event.repeat` が真のEnter（押しっぱなし）は、保存・確定の処理をしない。
4. それ以外を、通常のキー操作として扱う。
5. 科目や取引先の候補欄は、変換中の文字（`compositionupdate`）でも候補を絞る。選ぶのは、変換が終わってからのEnterか矢印だけにする。

フォームの暗黙の送信には頼りません。`<form>` の `submit` は常に `preventDefault` し、保存は、キー処理かボタンのクリックからだけ呼びます。50ミリ秒は経験値で、ブラウザやOSごとの保証はありません。

この判定は `ui/js/ime.js` の1つの関数に閉じ込め、全画面から使います。Nodeの試験と、Chromiumの変換の模擬（`Input.imeSetComposition`）で確かめます。AC-05.2 の自動の試験はChromiumの範囲です。SafariとFirefox、Windowsの変換は、公開の前に人が確かめます。

## 全体のキー

文字入力の欄にいるとき（変換中を含む）は、1文字のキーは働きません。

| キー | 動き |
|---|---|
| Ctrl/Cmd+K | コマンド一覧（画面の移動、主な操作、科目・仕訳の検索） |
| `g` のあとに `h` `n` `i` `j` `r` `w` `s` | ホーム、取引の登録、未確認、仕訳帳、帳票、口座、設定へ |
| `n` | 取引を登録 |
| `/` | 一覧の検索欄へ |
| `?` | ショートカットの一覧 |
| Esc | 閉じる、取り消す、候補を閉じる。検索欄では、欄から抜ける |

**1文字のキーは切れる**（WCAG 2.1.4、AC-10.5）。ショートカットの一覧の小窓（`?`、サイドバーの「ショートカット」）の先頭にある「1文字のショートカットを使う」と、Ctrl/Cmd+K の「1文字のショートカットを切り替える」で切り替える。既定は使う。設定はブラウザに覚える（端末ごと）。

- 切ると止まるもの: 文字の欄の外で押す、修飾キーなしの1文字。`g` のあとの文字、`n`、`/`、`?`、画面が決めた `1` `2` `3`（登録）・`j` `k` `e` `v` `[` `]`（仕訳帳）・`[` `]`（帳票）。表の該当する行に「いま切ってあります」と出る。
- 切っても働くもの: Ctrl/Cmd を伴うキー、Esc、Enter、Tab、矢印、部品にフォーカスがあるときだけ働くキー（未確認の行の `x` と Shift+Space、日付の欄の `t` `+` `-`、種別の欄の `1` `2` `3`、候補の一覧の矢印）。
- 切っても、キーの表示と `aria-keyshortcuts` は残る。隠すかどうかは未決（`spec-issues.md`）。

## 取引の登録

- 並びは、種別、日付、金額、科目、口座、税区分、取引先、摘要、割合。Tabで順に進み、Enterも次の欄に進む（変換中を除く）。
- 最後の欄のEnter、またはCtrl/Cmd+Enterで保存。保存後は金額に戻る。
- 種別の欄では `1` `2` `3` で支出・収入・振替を選ぶ。
- 日付の欄: `t` で今日、上下の矢印と `+` `-` で1日ずつ。「1005」「10/5」「20261005」を受け付ける。
- 金額の欄: 全角の数字、カンマ、`1000+650` のような四則を受け付ける。
- 科目と口座の欄: 打った文字で絞る。漢字、ひらがなの読み、コードのどれでも探せる。上下の矢印で選び、Enterで決める。
- 科目と口座の欄で、打った文字に合う候補が無いまま Enter を押しても、次の欄へは進まない。「合う科目がありません」の一言を出し直す（保存まで気づけないため）。科目の候補には、口座の親の科目（現金・預金）を出さない。口座の「現金」だけが出る（AC-02.9）。
- 事業の割合の欄は、入ったら全体が選ばれる（Enterで入っても、Tabで入っても同じ）。範囲外（0〜100の整数でない）になった時点で、欄の下に誤りを出す。
- 取消と訂正の確認の小窓は、保存の画面を開いたキーと同じ Ctrl/Cmd+Enter でも進める（ボタンにもキーを書く）。
- Tab の順は、最後の欄 → やめる → 保存 → 保存して続ける → テンプレートに登録。「入力の形」のタブは ← → で選び、選んでもフォーカスはタブに残る（マウスで押したときは最初の欄へ移る）。
- 保存で誤りがあれば、保存の帯に「2か所を直してください：金額、科目」と出す（`role="alert"`）。保存を試みたときの結果なので、欄を直したり入力の形を切り替えたりすると消える。「仕訳で入力」では「1行目の科目」「貸借の差」のように行の番号をつける。明細の欄の名前も「1行目 科目」「2行目を消す」のように行の番号を含み、行を足す・消すたびに振り直す。
- 締めた日以前の日付は、欄を確定した時点で、締めた日つきで断る（「2026年9月30日まで締めてあるため、この日付には登録できません。」）。サーバーに断られた文にも、締めた日と直し方を入れる（AC-06.3）。

## 未確認の一覧

| キー | 動き |
|---|---|
| 上下の矢印 | 同じ列の隣の行へ（候補欄が閉じているとき）。**税区分の欄では、値を1つずつ切り替える**（行は移らない） |
| Tab / Shift+Tab | 次のセル、前のセルへ |
| Enter（科目の候補が開いていて、印がある） | その候補を選び、行を確定する行にして、次の行の科目の欄へ進む（1回で済む） |
| Enter（候補が閉じている） | 科目があれば、行を確定する行にして次の行へ。無ければ「科目を選んでください」と出して動かない |
| Ctrl/Cmd+Enter | 確定する行を確定する（先に、件数と、入金の合計・出金の合計の確認が出る） |
| `x`（行にフォーカス） | 無視する |
| Ctrl/Cmd+Z（欄に入力していないとき） | 最後に無視した行を戻す |
| Shift+Space | 確定する行の印を付ける、外す。印は、絞り込みやページを変えても保たれる。画面を離れたり読み込み直したりすると消える（科目・税区分・取引先・割合は、下書きに保存されているので残る） |

## 仕訳帳

`j` `k` または上下の矢印で行を動かし、Enterで詳細を開く。`e` で訂正、`v` で取消、`[` と `]` で前の月と次の月へ移る。検索欄で ↓ を押すと、一覧の先頭の行へ移る（Enter の前の打ちかけの文字があれば、先に探してから移る）。

取消や訂正のあとは、一覧を読み直しても、その仕訳の行へフォーカスを戻す。詳細の板を閉じると、開く前の画面へ戻り、開いた行へフォーカスを戻す。元帳やホームから開いたときはその画面へ、仕訳帳の一覧から開いたときは検索の条件のままの一覧へ戻る（訂正の画面のアドレスの `back` に戻り先を持ち回る）。

## フォーカスと読み上げ

- フォーカスの輪は、ライトとダークの両方で3:1以上の差があり、常に見えること。
- 画面を切り替えたら、本文の見出しへフォーカスを移す。**ただし、取引の登録・訂正の画面は、最初の入力欄（新規は日付、訂正は金額）へ移す。** `n`・`e` は、打ち始めるために開くので、見出しから日付まで Tab を4回押させない（2026-10-15 の体験の評価で、評価者2人が指摘）。見出しは、ページの表題と、フォームの名前（`aria-labelledby`）で読み上げに伝える。
- 通知とエラーは `aria-live` で読み上げる。通知は、開いている小窓（`<dialog>`）より前面に出す。操作つきの通知は、10秒以上出し、焦点やマウスが乗っている間は消さない。置き場所は[画面の仕様（2）](screens-other.md)。
- 欄を出た時点の誤りは、欄の下の読み上げの領域（空のうちから置いた `aria-live="polite"`）で知らせる。同じ文を入れ直しても読み直さず、保存で新しく出た誤りだけが、欄ごとに1回読まれる。
- Ctrl/Cmd+K のコマンド一覧は、「編集」「修正」「削除」と打っても、訂正・取消の項目が出る（どちらも仕訳帳へ移る）。
- 先頭に「本文へ移動」のリンクを置く。
