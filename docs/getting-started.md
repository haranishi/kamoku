# 使い方: 動かして、自分の帳簿を始めるまで

v0.1-alpha の手順です。まだ配布用のアプリはなく、ソースから動かします。所要時間の目安は、最初のビルドが数分、そのあと15分以内に画面を見られることです。

## 必要なもの

- Rust 1.88以上（[rustup](https://rustup.rs/) で入ります）
- Cのコンパイラ。SQLiteを一緒にビルドするためです。macOSなら `xcode-select --install`、Ubuntuなら `sudo apt install build-essential`、Windowsは Visual Studio の Build Tools
- ブラウザ（最新のChrome、Safari、Firefox、Edge）。自動の試験は Chromium だけで、Safari と Firefox での確認は残っています。

CIは Linux と macOS で動いています。Windows向けの処理は書いてありますが、動かして確かめていません。

## 1. デモで試す

```
git clone https://github.com/haranishi/kamoku
cd kamoku
cargo run -p kamoku-app -- demo
```

ブラウザが開き、架空の事業の2026年の帳簿が見られます。開かないときは、ターミナルに出た `http://127.0.0.1:8765/?t=...` のアドレスを、自分でブラウザに貼ってください。アドレスの `t=` の後ろは、起動のたびに変わる合言葉です。人に教えないでください。

デモは、起動のたびに、新しい一時フォルダに作ります（古いデモのフォルダは消しません。OSの一時フォルダの掃除に任せます）。本物の帳簿の置き場所には触りません。止めるときは、ターミナルで Ctrl+C を押します。

まず、次の順に触ると、全体が分かります。

1. **ホーム**: 「次にやること」に、未確認の取引の件数が出ます。
2. **未確認**: 科目を選んで Enter を押すと、次の行へ進みます。最後に Ctrl+Enter（macOSは Cmd+Enter）で、まとめて確定します。
3. **取引を登録**（`n` キー）: 金額・科目・口座を入れて、保存の前に、仕訳のプレビューを見ます。
4. **仕訳帳**: 1件を開くと、履歴と、訂正・取消のボタンが出ます。
5. **帳票**: 損益計算書、貸借対照表、試算表、総勘定元帳を見ます。

画面のどこからでも、Ctrl+K（macOSは Cmd+K）でコマンド一覧、`?` でショートカットの一覧が出ます。

## 2. 自分の帳簿を始める

```
cargo run -p kamoku-app -- serve
```

初回は初期設定の画面が開きます。事業者名と課税の区分（免税か課税）、口座、期首残高の順に決めます。期首残高が分からなければ、0のままで進められます。あとから、設定の画面で見直せます。

帳簿は、SQLiteのファイル1つ（`kamoku.db`）に入ります。置き場所は次のとおりです。

| OS | 既定の置き場所 |
|---|---|
| macOS | `~/Library/Application Support/kamoku/` |
| Linux | `$XDG_DATA_HOME/kamoku/`（無ければ `~/.local/share/kamoku/`） |
| Windows | `%APPDATA%\kamoku\` |

別の場所に置くなら、`--data フォルダ` か、環境変数 `KAMOKU_DATA` で指定します。

## 3. 明細のCSVを取り込む

1. 銀行やカードのサイトから、明細のCSVをダウンロードします。
2. 「取込」の画面で、口座を選び、CSVを置きます。
3. 日付・摘要・金額の列の対応を確かめます。列の対応は、口座ごとに覚えます。
4. 「新規」「重複」「読めない」の件数を見て、取り込みます。
5. 取り込んだ明細は「未確認」に並びます。確定するまで、仕訳帳にも帳票にも出ません。

同じファイルを2回取り込んでも、二重には入りません。期間が重なる別のファイルでも、重なった分は入りません。ただし、同じ日・同じ金額・同じ摘要の別の取引は、重複と判定されることがあります。重複の行は理由つきで見えるので、取り込むと決めれば取り込めます。

カードの引き落としは、科目にカードの口座を選びます。費用の科目を選ぶと、カードで買った分と二重の経費になります（[よくある質問](faq.md)）。

## 4. 壊れていないかを確かめ、控えを取る

- 設定の画面の「台帳を検査する」で、連鎖を最初から検証します。
- 末尾のハッシュ（画面の「写し取る」）を、紙・メール・メモなど、帳簿の外に控えておくと、あとで「控えたときの帳簿に戻っているか」を照合できます。末尾の削除は、これでしか見つかりません。
- バックアップは、設定の画面から取れます。コマンドでも取れます。

```
cargo run -p kamoku-app -- verify
cargo run -p kamoku-app -- backup --out ~/kamoku-backup.db
```

## 困ったとき

| 症状 | 対処 |
|---|---|
| ブラウザが開かない | ターミナルに出たアドレスを、自分で貼ります |
| 「合言葉が必要です」と出る | 起動のたびに合言葉が変わります。ターミナルの新しいアドレスから開き直します |
| ポートが使用中 | 次の番号を自動で試します。`--port 番号` でも指定できます |
| 画面の上に警告の帯が出て、書き込めない | 台帳の検証に失敗した状態です。壊れた連番の手前までを、読み取り専用で見せています。`kamoku verify` で、最初に壊れた場所を確かめ、バックアップから戻してください |
| 他の場所で更新されたと出る | 同じ帳簿を、別のプロセスが書き換えました。画面を読み込み直します |

実際の帳簿・領収書・口座の明細は、Issueやサンプルに貼らないでください。
