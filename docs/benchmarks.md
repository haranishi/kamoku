# 速さの測定: 目標と、実測の結果

[非機能の要件](spec/nfr.md)の速さの目標5つは、どれも、実測が目標の3分の1以下でした。ただし測ったのは、1台の Apple M4 Pro（macOS）だけです。ほかの機種・OS・ブラウザは測っていません。結果は 2026-10-14 のものです。

## 結果

| 項目 | 目標 | 条件 | 実測（3回の範囲） |
|---|---|---|---|
| 台帳の起動時の検証 | 1秒以内 | 10万イベント | 262〜266ミリ秒 |
| 仕訳の追記（1件） | 20ミリ秒以内 | 10万イベントの台帳 | 0.65〜0.89ミリ秒 |
| ホームのまとめの応答 | 50ミリ秒以内 | 1万件の仕訳 | 中央値 2.6〜2.9ミリ秒（最大でも3.4ミリ秒） |
| CSVの取込 | 1,000件を1秒以内 | 合成データ1,000行 | 18〜22ミリ秒（送る 0.5〜0.7、確かめる 4〜5、取り込む 14〜17） |
| 画面の操作の応答 | 100ミリ秒以内 | 未確認200行で、科目の読みを3文字打つ | 中央値 4〜5ミリ秒 |

未達の項目はありません。「起動時の検証」は、起動のたびに、すべての記録のハッシュの連鎖を最初から確かめる処理です。10万イベントは、年に5,000仕訳として10年分にあたります。

## 測った環境

- チップ: Apple M4 Pro、メモリ 48GB、macOS 27.0.1
- Rust 1.99.0、`--release` のビルド（debug ビルドは数倍遅くなります）
- データは、すべて合成データです。ファイルの置き場所は一時フォルダで、ディスクの速さの影響を受けます。

## 測り方

最初の4項目は、`cargo run` で動く2つの測定プログラムが、同じパソコンの中で測ります。

```
cargo run --release -p kamoku-store --example bench   # 起動時の検証、1件の追記
cargo run --release -p kamoku-app --example bench     # ホームのまとめ、CSVの取込
```

- ホームのまとめは、実際のサーバーに30回問い合わせた、接続から応答の終わりまでの時間です。
- CSVの取込は、実際のサーバーへ、ファイルの送信・確かめ・取り込みの3つの要求を順に送った時間の合計です。
- 画面の操作の応答は、ブラウザ（Chromium）の試験 `e2e/bench-response.spec.mjs` が測ります。科目の欄に打った文字の入力イベントから、候補が出て、次の描画の枠が作られるまでを、ページの中の時計で測り、20回の中央値を出します。Playwright とのやりとりの時間は含みません。

## 測っていないこと

- Windows・Linux、古いパソコン、ブラウザごとの違い。
- 10万イベントを超える台帳。目標は10万イベントまでで、それ以上は保証しません。
- メモリの使用量、起動から最初の画面が出るまで、複数のブラウザの画面を同時に開いたとき。
- 実際の帳簿での長期の利用。実測は、合成データの1回の測定です。
- 人がキーボードだけで100件を確定する時間（[試験の地図](testing.md)の「自動では確かめていないこと」）。
